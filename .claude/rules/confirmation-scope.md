# 確認範圍 — 什麼時候才停下來問人

自主執行（`/harness-work`、`/goal`）時，**只有以下三種情況**可以停下來問使用者，
其餘一律自行決策、留一行理由、繼續做。使用者可以事後從結果軌道修正。

## 可以問的三種情況

1. **外部送信**：git push、建立/合併 PR、發 Release、任何把內容送出專案外的操作
2. **安全風險**：帳密或秘密可能外洩、破壞性操作（`rm -rf`、`git reset --hard`、force push）、
   任務需求與安全 invariant（自動登入不重試等，見 CLAUDE.md）衝突
3. **原始需求可能達不成，或解釋會改變**：任務描述與程式碼現況矛盾、DoD 無法滿足、
   必須違反「輕量」目標或改變架構前提（如業務邏輯進 Rust 側）才能實作

## 不問的情況（自行決策 + 一行理由）

| 場面 | 決策基準 |
|---|---|
| 審查對象有多個候選 | working tree 未提交變更 > `main..HEAD` > 最近 commit，取第一個 |
| 命名、檔案位置、實作細節 | 跟隨現有慣例，取最一致的一種 |
| 測試怎麼寫 | 跟隨 `tests/` 現有風格 |
| commit message | Conventional Commits + 繁中，自行生成 |
| 文件要不要同步 | 行為變更就同步，不問 |
| 輕微的範圍調整 | 不改變任務解釋就直接做並在回報中說明；會改變解釋則屬第 3 類 |
